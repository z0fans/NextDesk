# 修复应用内更新下载卡住 (0%) 问题

## 根因分析

从 `latest.json` 内容发现 **两个关键问题**：

### 问题 1: 版本号未同步（主要原因）

`tauri.conf.json` 和 `Cargo.toml` 中的 version 仍为 `1.0.91`，导致：
- `latest.json` 的 `version` 字段为 `"1.0.91"`
- Windows 安装包文件名为 `NextDesk_1.0.91_x64-setup.exe`
- **Tauri updater 插件 `check()` 对比 version 字段后认为当前已是最新版本，返回 null**
- 前端 `handleDownloadAndInstall()` 在 `if (!update) return;` 处直接退出，**下载从未开始**

```json
// latest.json 内容（有问题的版本号）
{
  "version": "1.0.91",  // ← 应该是 1.0.92
  "platforms": {
    "windows-x86_64": {
      "url": ".../NextDesk_1.0.91_x64-setup.exe"  // ← 文件名也含旧版本
    }
  }
}
```

### 问题 2: GitHub 下载需要代理（次要原因）

Tauri updater 插件默认直连下载，中国用户无法直连 `github.com`/`release-assets.githubusercontent.com`。即使版本号修复后，下载可能仍会超时失败。

> [!IMPORTANT]
> **问题 2 暂不在本次修复范围内**，因为需要大幅修改 Tauri updater 插件逻辑（自定义 HTTP client + SOCKS5 代理），复杂度较高。目前先修复版本号问题使功能恢复正常，代理下载的问题可在后续版本中处理（用户在使用应用时通常已启动 Clash 引擎，系统代理可能已生效）。

## 修复方案

### 版本号同步

#### [MODIFY] [tauri.conf.json](file:///Users/yuu/Downloads/vibe_coding/rdp_project/NextDesk/src-tauri/tauri.conf.json)

将第 3 行 `"version": "1.0.91"` 改为 `"version": "1.0.92"`

#### [MODIFY] [Cargo.toml](file:///Users/yuu/Downloads/vibe_coding/rdp_project/NextDesk/src-tauri/Cargo.toml)

将第 3 行 `version = "1.0.91"` 改为 `version = "1.0.92"`

### 前端下载错误处理改进

#### [MODIFY] [App.tsx](file:///Users/yuu/Downloads/vibe_coding/rdp_project/NextDesk/frontend/src/App.tsx)

在 `handleDownloadAndInstall()` 中，当 `check()` 返回 null 时，添加错误状态提示而不是静默返回（这样即使以后再出现此问题，用户能看到反馈）。
