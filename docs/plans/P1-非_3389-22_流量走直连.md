# P1：非 3389/22 流量走直连

## 问题

入口节点 198.176.49.82 上，route-monitor 显示 `google.com:443` 等普通流量仍走中转 `US-EAST (148.135.184.12:16779)`。
路由规则里写 `"outboundTag": "direct"` 时报 `non existing outTag: direct`。

## 根因

XrayR 自动生成的 freedom outbound tag 是动态的：`{NodeType}_{ListenIP}_{Port}`（如 `Shadowsocks_0.0.0.0_24016`），
不叫 `direct`。所以 route.json 中引用 `direct` 找不到 outbound。

## 方案

在服务器的 `custom_outbound.json`（通过 `OutboundConfigPath` 加载）中添加一个 tag 为 `direct` 的 freedom outbound，
然后在 `route.json` 的兜底规则中引用它。

### 需要在入口节点 198.176.49.82 上操作：

#### 步骤 1：修改 custom_outbound.json

在现有的 outbound 数组中**追加**一个 freedom outbound：

```json
{
  "tag": "direct",
  "protocol": "freedom",
  "settings": {
    "domainStrategy": "AsIs"
  }
}
```

完整的 `custom_outbound.json` 应该类似：

```json
[
  {
    "tag": "US-WEST",
    "protocol": "vless",
    ...现有中转配置...
  },
  {
    "tag": "US-EAST",
    "protocol": "vless",
    ...现有中转配置...
  },
  {
    "tag": "direct",
    "protocol": "freedom",
    "settings": {
      "domainStrategy": "AsIs"
    }
  }
]
```

#### 步骤 2：修改 route.json（或 route-rdp-us-west.json）

在 rules 数组末尾增加兜底规则，将非 3389/22 流量走直连：

```json
{
  "domainStrategy": "AsIs",
  "rules": [
    {
      "type": "field",
      "ruleTag": "rdp-ssh",
      "port": "3389,22",
      "outboundTag": "US-WEST"
    },
    {
      "type": "field",
      "ruleTag": "direct-all",
      "network": "tcp,udp",
      "outboundTag": "direct"
    }
  ]
}
```

> Xray 路由按 rules 顺序匹配，3389/22 先命中第一条走 US-WEST，
> 其余所有流量命中第二条走 direct（入口本地出站）。

#### 步骤 3：重启 XrayR

```bash
systemctl restart XrayR
```

#### 步骤 4：验证

```bash
# 1. 查看 XrayR 启动日志，确认无 "non existing outTag" 错误
journalctl -u XrayR --no-pager -n 30

# 2. 用 route-monitor 验证普通流量走向
# 期望：google.com:443 等应走 direct，3389/22 应走 US-WEST
```

## 验证计划

> [!IMPORTANT]
> 此修改需要在远程服务器 198.176.49.82 上执行，无法在本地自动化验证。

### 手动验证步骤

1. SSH 到入口节点 `198.176.49.82`
2. 备份当前配置：`cp /etc/XrayR/custom_outbound.json /etc/XrayR/custom_outbound.json.bak.$(date +%Y%m%d%H%M)`
3. 按上述方案修改 `custom_outbound.json` 和 route 配置
4. `systemctl restart XrayR`
5. `journalctl -u XrayR --no-pager -n 30` — 确认启动无错误
6. 通过 Clash 访问 google.com，然后在 route-monitor 中确认流量走的是 `direct` 而非 `US-EAST/US-WEST`
7. 通过 Clash 连接 RDP (3389)，确认仍走 `US-WEST`
