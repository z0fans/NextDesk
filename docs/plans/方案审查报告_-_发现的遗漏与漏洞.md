## 🔴 严重遗漏

### 漏洞 1: `.env` 中 reCAPTCHA SECRET 密钥

**现状**: `.env` 文件包含 `RECAPTCHA_V3_SECRET=6LfXPW...`
- Secret Key 应**只存在服务端**，不应出现在客户端 Electron 应用中
- 虽已在 `.gitignore` 中排除，但打包后会嵌入 `asar` 可被提取

**方案建议**: 新增 **P0-6: 迁移 reCAPTCHA 验证到服务端**
- reCAPTCHA v3 的 `secret` 验证应通过你的后端 API 调用
- Electron 客户端只负责获取 token → 发送到你的服务端 → 服务端调用 Google API 验证

---

### 漏洞 2: `index.ts` 中 reCAPTCHA 模块独立使用 Puppeteer

**现状**: `index.ts:780-830` 有独立的 `getRecaptchaV3Score()` 函数
- 直接调用 `launchBrowser()` (Puppeteer)
- 使用 `proxy-chain` 进行代理桥接
- 这段代码**不在 `bot-engine/` 目录下**，P1-6 迁移方案**完全没覆盖**

**影响**: 迁移后 reCAPTCHA 测试功能将**完全失效**

**修复**: P1-6 子阶段 ➌ 需明确包含：
- `index.ts` 中 `getRecaptchaV3Score()` 和 `testRecaptchaV2()` 的 Playwright 适配
- 这两个函数也需要改用 Camoufox 启动浏览器

## 🟡 重要遗漏

### 漏洞 3: `proxy-chain` 与 Camoufox 的兼容性

**现状**: `browser.ts` 使用 `proxy-chain` 库做 SOCKS5 代理桥接
- Puppeteer 不原生支持 SOCKS5 认证，需要 `proxy-chain.anonymizeProxy()` 中转
- **Camoufox 原生支持代理**（含 SOCKS5 认证），通过 `proxy` 参数传入

**影响**: 迁移后 `proxy-chain` 可能**不再需要**，但需要验证：
- Camoufox 的 proxy 参数是否支持 `socks5://user:pass@host:port`
- 如果支持，可移除 ~50 行 proxy-chain 桥接代码

**修复**: P1-6 子阶段 ➋ 需增加 proxy 兼容性验证步骤

---

### 漏洞 4: `closeBrowser()` 含 proxy-chain 清理逻辑

**现状**: `browser.ts:397-417` 的 `closeBrowser()`:
```typescript
export async function closeBrowser(browser: Browser) {
  // 关闭 proxy-chain 服务器
  // 关闭 browser
}
```
- `bot-engine/index.ts` 中有 **10+ 处** 调用 `closeBrowser()`
- 此函数不仅关闭浏览器，还清理 proxy-chain 资源

**修复**: P1-6 需明确重写 `closeBrowser()`，处理 Playwright context 清理

---

### 漏洞 5: `behavior/scheduler.ts` 引用 `Browser` 类型

**现状**: `behavior/scheduler.ts:1` → `import type { Page, Browser } from 'puppeteer'`
- 方案中 behavior/ 文件只标注为"改 import"
- 但 `scheduler.ts` 使用了 `Browser` 类型（不仅是 `Page`）
- Puppeteer 的 `Browser` 和 Playwright 的 `Browser` 接口有差异

**修复**: 确认 `scheduler.ts` 中 `Browser` 的用法是否需要适配

---

### 漏洞 6: Electron 打包 Camoufox binary 体积

**现状**: 方案提到 `npx camoufox-js fetch` 下载 ~700MB Firefox
- 未说明 Electron 打包时如何处理这个 binary
- `asar` 打包会导致极大的安装包体积

**修复建议**: 新增打包策略：
- 方案 A: 首次启动时下载（类似 Puppeteer 的 `PUPPETEER_SKIP_DOWNLOAD`）
- 方案 B: binary 放在 `asar.unpack` 目录外
- 需在 Phase 3 测试阶段验证
