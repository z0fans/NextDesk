# Domain Docs

This repository uses the single-context layout.

When a task changes domain terminology, responsibilities, or architectural decisions, consult the relevant parts of `CONTEXT.md` and `docs/adr/`, when present. Use their terms consistently and surface a conflicting decision before changing the affected design.

Missing domain files are not blockers. Create or update them only when there is a domain decision worth recording; routine edits do not require a domain-document pass.
